# OLD vs NEW Deliverables File System - Comprehensive Map

## Summary

The DawinOS codebase has **TWO PARALLEL deliverables systems**:

1. **OLD SYSTEM (Item-Level Subcollection)** - `designProjects/{projectId}/designItems/{itemId}/deliverables`
   - Per-item deliverable management
   - Used by DeliverablesManager component
   - Mirrors to projectFiles collection

2. **NEW SYSTEM (Unified File Manager)** - `projectFiles` collection
   - Project-wide file management
   - Unified across all modules
   - Single source of truth for all file types
   - Used by UnifiedFileManager component

3. **LEGACY SYSTEM (Client Portal)** - `projectDeliverables` collection  
   - Quote/portal-specific deliverables
   - Separate from design items
   - Has its own CRUD functions

### CANDIDATES FOR DELETION:

1. **Old deliverables subcollection** after migration
   - All data in `designProjects/{projectId}/designItems/{itemId}/deliverables/*`
   - Ensure projectFiles collection has all the data first

2. **Deprecate DeliverablesManager component** 
   - Only update items at a time
   - UnifiedFileManager is the new standard

3. **Deprecate individual deliverable functions** from firestore.ts
   - `createDeliverable()`

   - `deleteDeliverable()`
   - `toggleDeliverablePortalSharing()`
   - `getPortalSharedDeliverables()`
   - `getProjectDeliverablesPerItem()`

4. **Deprecate useProjectDeliverables hook**
   - Use UnifiedFileManager's built-in hooks

5. **Deprecate deliverableAutoGenService** CSV upload logic
   - Only keep CSV generation, upload via new system

6. **Remove RAG auto-update from createDeliverable**
   - Move to UnifiedFileManager or separate service

   - No longer needed when old system is gone
